# Экраны матча, игрока и команды: вкладки и сворачиваемая шапка — дизайн

Дата: 2026-10-14. Статус: на ревью.

## 1. Цель и рамки

Переделать три вложенных экрана iOS-приложения (матч, игрок, команда), чтобы они были в одном стиле с остальным приложением:
- вверху панели навигации нет заголовка-повтора; главный блок экрана сам называет экран, а при прокрутке его мини-версия появляется в матовой панели;
- содержимое разложено по вкладкам (тот же стеклянный скользящий `SegmentedPicker`, что на экране турнира), а не одним длинным списком;
- появляются данные, которые уже собраны, но не показаны: составы на поле, последние матчи игрока, статистика по сезонам, карьера, трансферы команды, дата рождения, флаг и название страны.

**Входит:** правки трёх экранов iOS, расширение трёх ответов API (`/matches/{id}`, `/players/{id}`, `/teams/{id}`), тесты.

**Не входит:** тап по строке турнира под матчем (экрану турнира нужен тип соревнования, которого у матча нет), рост / нога / стоимость / контракт игрока, переход в клуб из карьеры, изменения сборщика и схемы БД (всё нужное уже в базе).

## 2. Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Как отдавать новые данные | Расширить существующие ответы, по одному запросу на экран | Объём мал (составы ~5 КБ, сезоны и карьера ~10 КБ); вкладки переключаются мгновенно, без отдельных спиннеров |
| Составы | Поле со схемой по координатам FotMob | Координаты есть у всех игроков старта (171 270 / 171 270) |
| Вкладки игрока | Matches · Stats · Career | Выбор пользователя |
| Вкладки команды | Results · Fixtures · Squad · Transfers | Выбор пользователя |
| Флаг | Картинка FotMob `images.fotmob.com/image_resources/logo/teamlogo/{код страны в нижнем регистре}.png` | Реальные изображения, не эмодзи (design.md §7); проверено для arg, eng, ksa, kvx, com |
| Название страны | Имя сборной из `teams` по `players.national_team_id`; иначе показываем код | Есть у 13 838 из 14 518 профилей (95 %); у FotMob коды FIFA (GER, NED, SUI), не ISO |

## 3. API (только добавления, старые поля не меняются)

### 3.1 `GET /matches/{id}` — поле `lineups`

```json
"lineups": {
  "home": {
    "formation": "4-3-3",
    "starters": [LineupPlayer],
    "subs": [LineupPlayer],
    "coach": {"id": 1, "name": "…", "photo_url": "…"},
    "unavailable": [{"player": PlayerRef, "reason": "injury", "expected_return": "Early November"}]
  },
  "away": { … }
}
```

- `LineupPlayer` = `{"player": PlayerRef, "shirt_number", "position", "x", "y", "rating", "captain", "sub_in", "sub_out"}`; `PlayerRef` = `{"id", "name", "photo_url"}`.
- Источник — таблица `match_lineups` (роли `starter`, `sub`, `coach`, `unavailable`) и `matches.home_formation` / `away_formation`.
- `starters` упорядочены по `y`, затем `x`; `subs` — сначала вышедшие (по `sub_in`), потом остальные по номеру.
- Нет строк состава у стороны → эта сторона `null`; нет ни одной → `"lineups": null`.
- `reason` — как в БД: `injury`, `suspension`, `internationalDuty` (или `null`).

### 3.2 `GET /players/{id}` — поля `country_name`, `flag_url`, `matches`, `seasons`, `career`

- `country_name`: имя команды с `id = national_team_id`, если она есть в `teams`, иначе `null`.
- `flag_url`: ссылка из §2 по `country_code`, `null` без кода.
- `matches`: последние 15 матчей, где игрок выходил на поле (`role = 'starter'` или `role = 'sub'` и `sub_in` задан), только `FT` и `LIVE`, новые сверху. Каждый — обычный объект матча (`match_json`) плюс `"rating"`, `"minutes"`, `"role"`.
  - `minutes`: старт — `sub_out` или 90; выход на замену — (`sub_out` или 90) − `sub_in`; не меньше 1. Добавленное время не учитывается (shortcut, см. §6).
- `seasons`: строки `player_seasons`, сезон по убыванию, внутри — по числу игр: `{"season", "competition": {"id", "name", "logo_url"}, "team": {"id", "name", "logo_url"}, "appearances", "goals", "assists", "rating"}`.
- `career`: строки `player_career`: `{"kind", "team": {"id", "name", "logo_url"}, "start_date", "end_date", "appearances", "goals", "assists"}`; порядок групп `senior`, `national`, `youth`, `coach`, внутри — по `start_date` по убыванию. `team.id` и `logo_url` — `null`, если у записи нет `team_id`.

### 3.3 `GET /teams/{id}` — `last` до 20, `next` до 10, поле `transfers`

```json
"transfers": {"arrivals": [Transfer], "departures": [Transfer]}
```

- `Transfer` = `{"player": PlayerRef, "team": {"id", "name", "logo_url"} | null, "date", "fee_eur", "fee_text", "on_loan"}`; `team` — другой клуб (откуда пришёл / куда ушёл).
- По 20 последних в каждой группе, новые сверху; продления контракта (`contract_extension`) не показываем.

## 4. iOS

### 4.1 Общее

- **Сворачиваемая шапка.** Модификатор на главном блоке экрана следит за его положением в системе координат прокрутки. Когда блок целиком ушёл под панель навигации, в центре панели (`ToolbarItem(placement: .principal)` через `GlassToolbarItem`, без системного стекла) плавно (0,2 с) появляется мини-версия; при возврате — исчезает. С «Уменьшением движения» — без анимации. `navigationTitle` на этих экранах пустой.
- **Вкладки.** `SegmentedPicker` сразу под главным блоком (как на экране турнира), содержимое — стеклянные карточки `CardSection` / `Rows` / `glassCard`. Отступы по иерархии design.md §5: заголовок секции → карточка 12, блоки 24.
- **Пустые вкладки** показывают `EmptyState`: «No events yet», «No stats yet», «No lineups yet», «No matches», «No transfers».

### 4.2 Матч (`MatchView`)

- Карточка матча — как сейчас. Под ней строка (не кнопка): логотип турнира 20 + «Premier League · Matchday 7» (`roundTitle`), `textSecondary`.
- Мини-шапка: логотип хозяев 24 · счёт «2 – 1» цифровым шрифтом · логотип гостей 24; до начала матча вместо счёта время «21:00».
- Вкладки **Events · Stats · Lineups**. По умолчанию Lineups, если матч не начался, иначе Events. Events и Stats — нынешние карточки.
- **Lineups:**
  - строка над полем: герб хозяев 24, название, справа схема «4-3-3» (`textSecondary`); такая же строка для гостей под полем;
  - поле: `glassCard` с пропорцией 9 : 16 (ширина : высота), разметка белыми линиями 15 % прозрачности (контур, средняя линия, центральный круг, штрафные);
  - хозяева в верхней половине (вратарь сверху), гости в нижней, зеркально по x; глубина FotMob 0,10…0,87 растягивается на половину поля между отступом 30 и средним зазором 30 (так линии, идущие через ≈ 0,19, не наезжают друг на друга);
  - игрок: фото 28 (круглое), клетка 64, под ним фамилия (последнее слово имени, `caption2`, 1 строка) и оценка цифрами (`textSecondary`, без плашки); тап → экран игрока;
  - под полем карточки: **Substitutes** (по команде: фото 32, имя, номер; у вышедших — `arrow.up` и минута выхода), **Coaches** (две строки), **Unavailable** (имя, причина «Injured» / «Suspended» / «International duty», ожидаемое возвращение); пустые карточки не показываем.

### 4.3 Игрок (`PlayerView`)

- Главный блок: фото 96, имя, ниже клуб (первая команда из `teams`) и номер: «Manchester City · No. 9».
- Мини-шапка: имя игрока.
- Карточка фактов: Position; Age «26 · 21 Jul 2000»; Country — флаг 20 + название (или код).
- Вкладки **Matches · Stats · Career**:
  - **Matches:** строки матчей как в ленте (`MatchRow(showDate: true)`), справа колонка: оценка цифрами и минуты «78'»; тап → матч;
  - **Stats:** `CardSection` на сезон (заголовок «2025/2026»), строки: логотип турнира, название турнира и клуб, колонки Apps · G · A · Rating (как в таблице, с подписями колонок над первой строкой). Заменяет нынешние карточки Goals / Assists / YC / RC;
  - **Career:** `CardSection` «Clubs», «National team», «Youth», «Coaching»; строки: герб, клуб, годы «2022 – now», справа игры и голы.

### 4.4 Команда (`TeamView`)

- Главный блок: герб 72, название. Мини-шапка: герб 20 + название.
- Вкладки **Results · Fixtures · Squad · Transfers**:
  - **Results / Fixtures:** одна карточка со строками `MatchRow(showDate: true)`;
  - **Squad:** как сейчас (группы по позициям);
  - **Transfers:** `CardSection` «Arrivals» и «Departures»; строка: фото 36, имя, ниже «from Leeds United · 1 Jul 2026» / «to Chelsea · …», справа «€45M» (из `fee_eur`), «Loan», «Free», «Undisclosed» или «—»; тап → игрок.

## 5. Проверка

- **Бэкенд (pytest):** по фикстурам `match.json`, `team.json`, `player_*.json`: форма `lineups` (обе стороны, порядок, `null` без состава), `matches` / `seasons` / `career` / `flag_url` / `country_name` у игрока, `minutes` для старта и замены, `transfers` без продлений, лимиты `last` / `next`.
- **iOS (XCTest):** разбор новых полей, включая `null`-составы и сторону без состава.
- **UI (XCUITest во временной копии):** скриншоты трёх экранов, каждой вкладки; прокрутка вниз → мини-шапка видна, вверх → скрыта; тап по игроку на поле открывает профиль.

## 6. Риски и упрощения

- `minutes` без добавленного времени — может показать 90' при фактических 95'. Заменить на длительность из событий, если понадобится точность.
- Составы появляются в базе, только когда сборщик забрал детали матча; для будущих матчей их чаще всего ещё нет — вкладка покажет «No lineups yet».
- 5 % игроков без полного названия страны покажут код FIFA.
